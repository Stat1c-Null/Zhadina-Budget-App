Keep it up to date as you work, not only at the end of a task. Before you finish a task, check whether what you changed or learned makes any note wrong or incomplete, and fix it.

| Note | Update it when |
|---|---|
| `Zhadina Budget App Home.md` | Status, stack, how to run the app, or the list of notes changes |
| `Architecture.md` | The API contract, data model, code map, or a design decision (ADR) changes |
| `Implementation Plan.md` | Work starts or finishes, the plan changes, or you find a known issue |

Rules:

- Edit the existing note that covers the topic. Add a new note only for a topic none of them covers, and link it from `Zhadina Budget App Home.md`.
- Write what is true now. Correct or remove outdated statements instead of adding contradicting ones after them.
- Record the reasoning and anything the code can't show: why a decision was made, what was tried and failed, what hasn't been verified. Don't paste in code.
- Only state what you checked. Mark anything inferred or unverified with 🟠.
- Never put real passwords, tokens, or connection strings with secrets in a note.
- Link notes with Obsidian `[[wiki links]]`.
- Read the relevant notes before relying on them, and check them against the code, because they can be out of date.
